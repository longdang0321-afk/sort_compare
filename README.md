## 2. 실험 방법

### 2.1 데이터 구조

```c
typedef struct {
    int key1;   // 정렬 기준
    int key2;   // 관찰용 (정렬 기준 아님)
    int order;  // 원래 입력 순서 (안정성 검사 전용, 정렬 기준 아님)
} Data;
```

`order`는 각 레코드가 처음 몇 번째였는지 기록한다. 정렬 알고리즘은 이 값을 사용하지 않고, 정렬이 끝난 뒤 같은 `key1`을 가진 레코드의 원래 순서가 유지되었는지 확인할 때만 사용한다. 이렇게 해야 알고리즘이 `order`를 몰래 참고하지 않고도 순서를 지키는지(= 진짜 안정성)를 검사할 수 있다.

### 2.2 실험 설정

| 항목 | 값 |
|---|---|
| 데이터 개수 N | 10,000 |
| 무작위 실험 반복 | 100회 (매 회 새 입력을 만들어 네 알고리즘이 같은 입력 사용) |
| key1 범위 | 0 ~ 1,000,000 (안정성 실험은 0 ~ 50) |
| 시드 | 2026 |

### 2.3 측정 기준

- **비교 횟수**: `key1` 사이의 비교만 센다.
- **이동 횟수**: `Data` 전체를 복사한 횟수를 센다.
  - 두 원소 교환(`swap_data`)은 임시 변수를 쓰므로 **3회**로 센다.
  - 선택 정렬은 `min != i`일 때만 교환한다.
  - 삽입 정렬은 임시 변수 저장 1회 + 한 칸씩 밀기 1회씩 + 최종 위치 삽입 1회로 센다.
- 입력 복사(`memcpy`), 입력 준비용 `qsort`, 결과 검사(`check_result`), 안정성 검사는 횟수에 포함하지 않는다.
- 실행 시간(초)은 측정하지 않았다. 알고리즘 자체의 작업량을 비교하기 위해 횟수만 사용했다.

### 2.4 입력 데이터 생성 방법

| 입력 | 생성 방법 |
|---|---|
| 무작위 | `gen_random()`으로 100회 생성 |
| 오름차순 (이미 정렬) | 무작위 데이터를 `qsort`로 정렬 (key1이 같으면 order 순) |
| 역순 | 오름차순 데이터를 뒤에서부터 복사 |
| 부분 정렬 | 오름차순 데이터에서 무작위 두 위치를 골라 서로 교환하는 작업을 500회 수행 |

**부분 정렬 데이터 생성 방법**: 완전히 정렬된 배열에서 출발해 `rnd(N-1)`로 뽑은 두 위치 `i`, `j`의 값을 500번 교환했다. 500은 `N * 5 / 100`으로 계산했다. 이 5%는 **교환 횟수가 N의 5%**라는 뜻이며, 실제로 위치가 바뀐 원소의 비율(최대 약 10%)과는 다르다. 즉 배열의 대부분은 제자리에 있고, 일부 원소만 멀리 떨어진 곳으로 옮겨진 상태이다. 이렇게 하면 "거의 정렬되어 있지만 일부 원소가 크게 어긋난" 입력을 만들 수 있고, 이것이 조기 종료 조건과 삽입 정렬에 서로 다른 영향을 주는지 볼 수 있다.

### 2.5 정렬 결과 검증

`check_result()`는 정렬 후 (1) `key1`이 오름차순인지, (2) 원본 레코드가 누락·중복·손상 없이 남아 있는지(`order`로 원본을 찾아 `key1`, `key2` 비교)를 확인한다. 모든 실험이 `OK`였고, 무작위 100회도 전부 통과했다 (`All 100 trials sorted and data preserved: YES`).

### 2.6 안정성 검증 방법

1. **작은 예제**: `(5,100) (5,200) (2,300)`처럼 key1이 같은 데이터 2개를 포함한 3개 데이터를 정렬해, 같은 key1(5)인 두 데이터의 순서가 바뀌는지 눈으로 확인한다.
2. **대규모 중복 키 실험**: key1을 0~50으로 제한해 같은 key1을 가진 데이터가 키 값마다 약 196개 있는 입력을 만든다. key1 범위가 넓으면 중복이 거의 없어 안정성 차이가 드러나지 않기 때문이다.
3. **위반 쌍 계산**: 정렬 후 인접한 두 원소가 key1이 같은데 `order`가 뒤집혀 있으면 위반으로 센다 (`stability_violations`). 0이면 `STABLE`, 아니면 `NOT STABLE`이다.

## 4. 결과 분석

### 4.1 비교·이동 횟수가 그렇게 나온 이유

**역전 쌍(inversion)**이란 앞에 있는 값이 뒤에 있는 값보다 큰 쌍을 말한다. 정렬은 결국 모든 역전 쌍을 없애는 일이고, 무작위 입력의 평균 역전 쌍은 N(N−1)/4 ≈ 24,997,500이다. 이 값으로 실험 결과 대부분이 설명된다.

- **선택 정렬**: 최솟값을 찾으려면 남은 구간을 끝까지 훑어야 하므로 입력과 상관없이 항상 N(N−1)/2 = **49,995,000**번 비교한다. 네 가지 입력 모두 같은 값이 나왔다. 반면 교환은 원소당 최대 1번이라 이동이 최대 3(N−1) = 29,997번으로 제한되고, 무작위 평균 29,970.69는 이 상한에 가깝다.
- **일반 버블 정렬**: `n-1`번의 순회를 무조건 수행하므로 비교는 입력과 무관하게 49,995,000번이다. 인접 원소를 교환할 때마다 역전 쌍이 정확히 1개 줄어들기 때문에 교환 횟수 = 역전 쌍 수이고, 교환 1회가 이동 3회이므로 이동은 **역전 쌍 × 3**이다. 무작위 평균 이동 74,995,936.56은 평균 역전 쌍(약 24,998,645)의 3배와 일치한다.
- **삽입 정렬**: 한 번 밀 때 역전 쌍이 1개 줄고 이동도 1회이다. 여기에 원소마다 임시 저장과 삽입 2회가 더해져 이동 = 역전 쌍 + 2(N−1)이다. 무작위 평균 약 24,998,645 + 19,998 ≈ 25,018,643으로 실험값과 같다. 비교는 역전 쌍 + (N−1) 근처이므로 무작위에서 선택/버블의 약 절반이다. 같은 역전 쌍을 해결하는데 버블은 교환(이동 3회), 삽입은 밀기(이동 1회)를 쓰므로 **이동이 약 1/3**이다.

### 4.2 입력의 초기 정렬 상태가 성능에 미치는 영향

**선택 정렬**: 비교 횟수가 입력 상태에 전혀 영향을 받지 않는다. 이미 정렬되어 있어도 최솟값을 확인하려고 끝까지 훑기 때문이다. 이동 횟수만 달라진다. 정렬된 입력은 `min == i`이므로 교환이 한 번도 일어나지 않아 0이고, 부분 정렬은 1,509(교환 약 503회), 역순은 15,102이다. 역순의 이동 15,102는 교환 5,034회에 해당하는데, 이론값 N/2 = 5,000보다 약간 많다. 중복 키 때문으로 추정한다.

**일반 버블 정렬**: 비교는 항상 49,995,000번이고, 이동만 역전 쌍 수에 비례해 0 → 8,904,009(부분) → 74,995,936(무작위) → 149,984,844(역순)로 커진다. 역순의 역전 쌍은 최대값 49,995,000이 아니라 49,994,948인데(이동 149,984,844 ÷ 3), 차이 52는 key1이 같은 쌍(역전이 아님)의 수이다.

**조기 종료 버블 정렬**: 입력 상태에 가장 민감하다. 정렬된 입력에서는 첫 순회에서 교환이 없어 바로 종료하므로 비교가 9,999번이다. 반면 역순에서는 일반 버블과 결과가 같다. 이 차이의 이유는 4.3에서 자세히 분석한다.

**삽입 정렬**: 비교·이동이 역전 쌍 수에 거의 비례한다. 정렬된 입력은 비교 9,999번(원소마다 1번), 부분 정렬은 비교 2,978,002번으로 무작위(약 25,008,635번)의 약 12% 수준이다. 역순은 비교 49,995,000번으로 최악이며 선택/버블과 같아진다. 정렬된 입력의 이동 19,998은 실제로 밀린 원소는 없고 측정 기준상 원소마다 임시 저장 1회와 삽입 1회를 세었기 때문이다.

### 4.3 조기 종료 조건의 영향

조기 종료는 "한 순회에서 교환이 한 번도 없으면 이미 정렬된 것"이라는 조건으로 남은 순회를 건너뛴다. 그런데 버블 정렬은 한 순회에서 작은 값이 **왼쪽으로 최대 한 칸**씩만 이동한다. 그래서 필요한 순회 횟수는 "어떤 원소 앞에 있는 자기보다 큰 값의 개수"의 최댓값에 가깝다. 이 값이 크면 교환이 마지막 순회까지 계속 발생해 조기 종료가 거의 일어나지 않는다.

- **오름차순**: 필요한 순회가 1번이라 비교가 49,995,000 → 9,999번으로 99.98% 줄었다.
- **무작위**: 평균 절감이 10,568번(0.02%)뿐이다. 무작위 배열에서는 작은 값이 뒤쪽에 있을 가능성이 높고, 그 값이 맨 앞까지 가는 데 순회가 거의 N번 필요해서, 교환이 없어지는 시점이 전체 순회의 거의 끝이기 때문이다.
- **부분 정렬**: 절감이 37,950번(0.08%)뿐이다. 500번의 무작위 교환 중 작은 값이 뒤쪽으로 멀리 옮겨진 경우가 있으면 그 값 하나를 제자리로 돌리는 데 수천 번의 순회가 필요하다. 즉 "거의 정렬"이어도 어긋난 원소 몇 개가 멀리 있으면 조기 종료는 도움이 되지 않는다. 반면 삽입 정렬은 어긋난 원소만 처리하므로 비교가 크게 줄었다.
- **역순**: 마지막 순회까지 교환이 발생하므로 이득이 전혀 없다 (차이 0).

조기 종료는 **교환을 줄이지 못하므로** 이동 횟수는 일반 버블과 모든 입력에서 같다. 절약되는 것은 교환이 없는 순회의 비교뿐이다.

### 4.4 삽입 정렬에서 `>`와 `>=`의 영향

삽입 정렬은 삽입할 값(`cur`)보다 큰 값을 오른쪽으로 밀고 멈춘 자리에 `cur`를 넣는다. 이때 같은 값을 만났을 때의 행동이 `>`와 `>=`에서 다르다.

- **`>` (안정)**: 같은 값을 만나면 **멈춘다**. `cur`는 같은 값들의 바로 **뒤**에 들어가므로 원래 순서가 유지된다. 작은 예제에서 `(5,100) (5,200)`이 그대로 유지되었다.
- **`>=` (불안정)**: 같은 값도 **밀어 버린다**. `cur`는 같은 값들의 **앞**에 들어가므로 같은 key1끼리 순서가 뒤집힌다. 대규모 실험의 violations 9,949는 전체 인접 쌍 9,999개 중 key1이 같은 인접 쌍 (10,000 − 51 = 9,949개, key1이 0~50의 51종류이므로)이 **모두** 뒤집혔다는 뜻이다. 오름차순 정렬 결과는 올바르지만 같은 값 사이의 순서만 완전히 반대가 된다.

성능에도 차이가 있다. `>=`는 같은 값까지 지나가야 하므로 비교가 약 980,145번(약 4.0%), 이동이 약 980,328번 더 많다. 이 추가량은 "key1이 같은 쌍"의 수 ≈ N² / (2 × 51) ≈ 98만 개와 거의 일치한다. 즉 부등호 하나를 `>`에서 `>=`로 바꾸면 안정성을 잃고 성능까지 나빠진다. 중복 키가 많을수록 이 차이는 더 커진다.

### 4.5 선택 정렬과 버블 정렬의 안정성

- **선택 정렬 (불안정)**: 최솟값을 앞쪽 위치와 **멀리 떨어진 곳에서 교환**한다. 이때 사이에 있던 같은 key1 데이터를 건너뛰어 순서가 뒤집힌다. 예제에서 맨 앞 `(5,100)`이 `(2,300)`과 교환되며 뒤로 밀려가 `(5,200)` 뒤에 위치했다. 대규모 실험에서도 violations 3,232가 나왔다.
- **버블 정렬 (안정)**: 인접한 두 원소만 비교하고 `>`일 때만 교환한다. key1이 같은 두 원소는 교환하지 않으므로 서로를 추월할 수 없다. 조기 종료 버전도 교환 조건이 같아 안정하다.

### 4.6 종합: 성능 차이가 생기는 원인

| 알고리즘 | 비교 (최선 / 평균·최악) | 이동 | 안정성 | 성능을 결정하는 요인 |
|---|---|---|---|---|
| 선택 정렬 | O(N²) / O(N²) | 최대 3(N−1) | 불안정 | 입력과 무관, 이동이 가장 적음 |
| 버블 정렬 | O(N²) / O(N²) | 역전 쌍 × 3 | 안정 | 항상 N−1번 순회, 교환 비용이 큼 |
| 조기 종료 버블 | O(N) / O(N²) | 역전 쌍 × 3 | 안정 | 필요한 순회 횟수(가장 멀리 있는 작은 값) |
| 삽입 정렬 (`>`) | O(N) / O(N²) | 역전 쌍 + 2(N−1) | 안정 | 역전 쌍 수 |
| 삽입 정렬 (`>=`) | O(N) / O(N²) | `>`보다 많음 | 불안정 | 같은 값 쌍의 수 |

- 무작위·역순·부분 정렬에서 버블 정렬의 이동은 삽입 정렬의 약 3배이다 (74.99M vs 25.02M, 149.98M vs 50.01M, 8.90M vs 2.99M). 같은 역전 쌍을 교환(이동 3회)으로 푸느냐 밀기(이동 1회)로 푸느냐의 차이이다. 정렬된 입력에서만 버블의 이동이 0으로 더 적은데, 이는 삽입 정렬의 이동 19,998이 측정 기준 때문이기 때문이다.
- 선택 정렬은 비교는 가장 많지만 이동이 가장 적다. 레코드가 커서 복사 비용이 큰 경우에는 이 특성이 유리할 수 있지만 안정성이 없다.
- 안정성이 필요하고 데이터가 어느 정도 정렬되어 있다면 삽입 정렬(`>`)이 가장 적합하다. 네 알고리즘 모두 O(N²)이므로 N이 큰 일반 데이터에는 O(N log N) 정렬이 필요하다.

## 5. 인공지능 활용 내용

- **활용한 AI**: Claude (Anthropic), ChatGPT (OpenAI)

- **README 작성**: Claude에게 `sort_compare.c`와 실행 결과(`output_result.txt`)를 제공하여 README 초안 작성과 결과 분석에 도움을 받았다. ChatGPT를 통해 수정된 코드의 실행 결과를 바탕으로 비교 횟수, 이동 횟수, 안정성 검증 결과 및 알고리즘별 성능 차이를 정리하는 데 도움을 받았다.

- **부분 정렬 데이터 생성 방법**: AI에게 부분 정렬 데이터를 만드는 방법을 질문하고, 정렬된 배열의 일부 데이터를 무작위로 교환하는 방법을 사용했다. 먼저 10,000개의 데이터를 첫 번째 키를 기준으로 오름차순 정렬했다. 그다음 배열에서 두 위치를 무작위로 선택하여 해당 위치의 데이터를 교환했다. 이 과정을 총 500회 반복하여 일부는 정렬되어 있지만 일부 위치는 바뀐 데이터를 만들었다. 교환할 때는 Key 1, Key 2, 원래 입력 순서를 하나의 데이터로 함께 이동했다. 500회는 전체 데이터 수 10,000의 5%에 해당하는 교환 횟수이다. 같은 위치가 여러 번 선택되거나 두 위치가 같을 수 있으므로, 정확히 500개의 데이터가 원래 위치에서 바뀌었다는 뜻은 아니다. 생성한 부분 정렬 데이터는 각 정렬 알고리즘에 동일하게 제공하여 비교 횟수와 데이터 이동 횟수를 측정했다.

- **코드 작성 및 수정**: ChatGPT에 정렬 알고리즘의 비교 횟수와 데이터 이동 횟수를 측정하는 방법, 버블 정렬의 조기 종료 조건, 삽입 정렬의 `>`와 `>=` 조건에 따른 안정성 차이를 질문하고 코드 작성·수정에 도움을 받았다. 이후 코드 검토를 요청하여 함수 포인터 대신 `switch`를 사용하고, 정렬 결과에서 데이터의 누락·중복과 두 키의 보존 여부를 확인하는 부분을 보완했다.

- **AI 결과에 대한 검증**: 프로그램을 실행하여 100회 무작위 실험과 입력 상태별 실험 결과를 확인했다. 선택 정렬과 일반 버블 정렬의 비교 횟수는 이론값인 `n(n-1)/2`와 비교했다. 또한 중복 키를 포함한 작은 데이터로 정렬 결과와 안정성을 검사하고, 삽입 정렬에서 `>`와 `>=`의 결과가 어떻게 다른지 확인했다.

## 6. 한계

- 실제 실행 시간은 측정하지 않고 비교/이동 횟수만 비교했다.
- N = 10,000 한 가지 크기만 사용했으므로 N에 따른 증가율은 이론(O(N²))에 의존해 해석했다.
- 부분 정렬 입력은 하나의 무작위 시드로 한 번만 만들었다. 교환 비율(5%)을 바꾸면 조기 종료의 효과가 어떻게 달라지는지는 확인하지 못했다.
